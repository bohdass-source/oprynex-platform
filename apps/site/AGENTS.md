Notes for AI coding agents working on the site (kept as written during development).
- Hosting: Cloudflare Worker "site" → https://site.oprynex.workers.dev, deployed with `bun run cf:deploy`.
- Database: Supabase project your-project-ref (Frankfurt), shared with the CRM (repo oprynex-app, Worker "app"). This repo owns migrations 0000–0099 (lead intake, chat quotas) in database/migrations; oprynex-app owns 0100+ (workspaces, lead pipeline, notes, tasks). New leads land in the Oprynex workspace through the leads.workspace_id default, so accept_lead needs no change; lead status values are new, contacted, proposal, won, lost, spam.
- Worker secrets: SUPABASE_URL, SUPABASE_SERVICE_ROLE_KEY (sb_secret_ key), ANTHROPIC_API_KEY, ALLOWED_ORIGINS. Never commit secrets or .env files.
- Before deploying: `bun run test:node26`, `bunx tsc --noEmit`, `bun run build`.

- Shared navigation, footer and CTAs live in the site component; content pages use dedicated TanStack routes to keep navigation and metadata consistent.
- Theme preference is browser-local presentation state, applied after hydration; dark remains the SSR default to avoid browser access during rendering.
- Datenschutz and Impressum render owner-approved German texts for every site language; operator name, address and email come from src/lib/operator.ts (owner-provided). AGB and AVV (src/lib/agb-text.ts, avv-text.ts, B2B only) and the Datenschutz text are example texts written for this project; they are not legal advice. Never invent operator data or legal terms.
- The chat calls a public AI server function only for free-text turns, with per-IP-hash and global daily quotas in a service-role-only database function; the system prompt lives in a server-only module, message texts are never stored or logged, and any failure falls back to local keyword scenarios.
- Cookie choices are browser-local, validated, restored after hydration and editable from the footer; optional tracking must check for explicit acceptance before loading or emitting events, so rejection and an absent choice never enable tracking.
- The shared contact schema requires explicit data-processing consent; reuse it for future delivery handlers to preserve validation at both boundaries.
- Lead submission uses a public POST TanStack server function and shared strict Zod schema; the reusable client helper preserves one submission contract for contact and future chat without adding Edge Functions.
- Leads and IP-hash rate limits have service-role-only grants and no RLS policies; one service-role-only database function locks per IP and atomically saves a lead plus rolling-hour quota to prevent concurrent oversubmission and quota consumption on failed inserts.
- Lead ingress checks approved origins and trusts only CF-Connecting-IP in production, failing closed when absent; local development uses the socket address or a shared local bucket, never forwarded client headers.
- The assistant renders a single trilingual prepared-scenario registry; state stays in the root-mounted widget across navigation, keywords run locally, and only explicit consented lead/handoff form submission uses the shared lead helper.
- Chat language is independent React state synchronized on site-language changes; a local heuristic runs before keyword routing, and browser speech recognition uses session-only inline consent and lifecycle cleanup so chat never changes site language or auto-submits dictation.

- Site language uses a shared React context in the root shell (including error/not-found views) and an explicit Russian-source translation dictionary; initialize German on every page load without restoring browser storage, keep manual selection during in-app navigation, and translate content and metadata without changing routes so every new visit starts in German.
- Each content route uses the shared SEO registry for unique metadata and a self-referencing canonical; keep the static sitemap aligned with public routes so search engines discover the same URLs. Client-only language choices are not separate indexable pages and must not be advertised with hreflang.
- The public address lives only in src/lib/site-url.ts (siteUrl, formerHosts). To move to an own domain run `bun scripts/move-domain.ts https://<domain>`: it rewrites siteUrl and the crawl files in public/ and keeps the old host as a permanent 308 redirect (src/lib/http-policy.ts). New requests land in the CRM; the site also sends one internal email per request to the secret NOTIFY_EMAIL through the Cloudflare send_email binding, which needs Email Routing kept on for the domain.
- Commercial offers (4 service pages: chatbot, website, custom CRM, consulting; cards, prices) come from one trilingual offers registry. Since 2026-11-07 Oprynex Cloud and MVP are no longer offered: their pages redirect permanently (MOVED_PAGES in src/lib/http-policy.ts) and the site, chat and crawl files must not mention them; the CRM app stays the owner's own tool; route SEO metadata is German at SSR, derived from the trilingual SEO registry, so crawlers see the default language.

- Every page shares one shell (src/components/site-shell.tsx, used by the root route): floating navigation to the site pages, the page, the original footer (emblem, owner and description, address, email, slogan, cookie and legal links), the assistant and the cookie dialog. The home page (/) is a landing built to the landing-page-design skill; only it plays the intro (CSS timeline, plays once per load, the cookie dialog waits for it). Copy lives in src/lib/landing-copy.ts; the flat tokens and the class mapping for the older pages live in src/landing.css, scoped by `:root:has(.lp)`, so the chat widget and cookie dialog follow them. Dark is the default; the light theme is black and white (white page, grey surfaces, all type black, muted type #404040) and bright gold (#DBA812, token --lp-gold) is used only for what glows: the rings around cards, the assistant button and the drawing behind the first screen; in the dark theme --lp-gold is white, so the dark theme is unchanged. The hero subline (.lp-hero-sub) is full white with a soft shadow in the dark theme and black in the light one. Only the Oprynex name and emblem carry over from the first gold theme.
- The opening words (hero badge, headline, subline and the intro slogan built from the headline) are the owner's own wording from the first version of the site; keep them, hyphens included. Offer cards (src/components/offer-card.tsx) show the registry category, a benefit line, the price and one centred "prices & details" button that flips the card to what is included (no "learn more" link on the front; the back keeps its link to the offer page); the cards, the assistant cards and the industry cards carry the same turning light ring as the assistant button, and the landing shows them in carousels that open on the second card with the centre card raised. All carousels (hero example pairs, offers, assistants) are endless: copies of the end cards sit beyond the real ones and the row is moved onto the matching real card once it rests (src/components/landing/carousel.tsx and carousel-loop.ts); pass real <li> elements as children so the copies can be marked aria-hidden and inert. The first screen is the headline with the two buttons on the left and, on the right, a project card per product that moves on by itself every 3 s (it stands still under the pointer, with keyboard focus inside, out of view, in a hidden tab, with reduced motion and after the visitor pressed pause); the card has three views (overview, key points, detail with the two windows: what the customer sees, what happens on your side) and the chosen view stays from case to case; the four promises (src/components/landing/hero.tsx) sit at the foot of the hero. Copy for the cases is in landing.examples. Prices come from src/lib/offers.ts (`prices`); in this public demo `eur()` prints "XXX €" for every amount. They fill only the price slots of the existing cards, offer pages and /preise (no extra tiers or sections); all amounts are net and the notes say 19 % VAT is added. The chat names the same starting prices: the prepared price answer (src/lib/chat-scenarios.ts) and the AI knowledge (src/lib/chat-knowledge.server.ts) are built from `prices` and the offers registry, so they cannot drift; the chatbot's monthly operation fee (`prices.chatbotMonthly`, shown on the back of its card and in the chatbot guides) is published since 2026-11-07; packages and timelines stay unpublished. Change a price in `prices`, never in a single string.
- Every page ends with the contact form (src/components/contact-section.tsx, shared with /contact through contact-form.tsx). Keep landing copy free of hyphens, exclamation marks and invented proof: no testimonials, client logos or prices until the owner supplies them (src/test/landing.test.tsx enforces the copy rules).

- Speed rules for the landing: the turning light ring is a transform on a pseudo element (.lp-glow::before), never an animated custom property; the hero photograph stays still (a moving picture under blurred panels is re-blurred on every frame); the carousel writes to the cards only when the middle card changes; Manrope is served from the project (@fontsource-variable/manrope), with no request to Google; the emblem is shown from a 192 px JPEG (public/brand/oprynex-emblem-192.jpg). Headings may break inside a word and shrink to 30 px under 420 px so long German words never widen the page. src/test/landing.test.tsx pins the load bearing rules of landing.css, because one careless edit once removed a whole block unnoticed.
- The intro (home page, black whatever the theme) shows its slogan and the word Oprynex in gold (.lp-intro-gold: a vertical gradient from #F6DC85 through #DBA812 to #B8860B, set per word because each word is animated alone); the skip button stays white.

- Search guides come from one trilingual registry (src/lib/guides.ts with guides-industries.ts and guides-services.ts; shared types in guides-base.ts), rendered by src/components/guide-page.tsx and linked from their offer page; the nine /industries cards link to their page. Each carries its own meta, Article and FAQPage markup built from the visible text. Amounts come from `prices`; state only facts the chat knowledge and the bot rules also state, keep every industry page's questions, flow and limits its own so they are not near-duplicates, and never promise legal compliance, rankings or client results. After adding one, update the GuidePath type, public/sitemap.xml and public/llms.txt.
